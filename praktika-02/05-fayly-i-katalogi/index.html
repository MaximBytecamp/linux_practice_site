§1Создание каталогов: mkdir

mkdirmake directory
mkdir [аргументы]… {путь}…

Создаёт каталог по указанному пути. Путей можно перечислить несколько через пробел — тогда создастся несколько каталогов сразу.

-p
создать все недостающие каталоги пути
-v
сообщать о каждом созданном каталоге

Обратите внимание на важное ограничение: mkdir создаёт один уровень вложенности. Команда mkdir /tmp/dir1/dir2/dir3 завершится ошибкой, если /tmp/dir1 ещё не существует, — родительский каталог должен быть на месте. Обойти это позволяет ключ -p (parents): он создаст всю цепочку разом.

Не сработает

mkdir /tmp/a/b/c

No such file or directory, если /tmp/a не существует.

Сработает

mkdir -p /tmp/a/b/c

Создаст a, внутри него b, внутри него c.

Попробуйте на своей системезадание 1
  1. Создайте папку test в домашней директории. Можете сначала перейти туда командой cd.
  2. Создайте одной командой три каталога dir1, dir2, dir3 внутри test.
  3. Проверьте результат: ls test.
  4. Попробуйте создать каталог /tmp/dir1/dir2/dir3 за одну команду. Что произошло?
  5. Добейтесь того же результата с ключом -p и проверьте: ls -R /tmp/dir1.

§2Создание файлов: touch

touch«прикоснуться»
touch {имя}…

Если файла нет — создаёт пустой файл. Если файл есть — обновляет время последнего изменения, не трогая содержимое.

Название команды объясняется её основным назначением: изначально touch придумали не для создания файлов, а для изменения их временных отметок — времени модификации и времени последнего доступа. «Прикоснуться к файлу», ничего в нём не поменяв. Побочный эффект — создание пустого файла, если его не было, — оказался настолько удобным, что стал основным способом применения.

Размер созданных файлов — ноль байт: они действительно пустые. Заполнять их мы научимся в следующей главе.

Попробуйте на своей системезадание 2
  1. Создайте в домашней папке несколько пустых файлов одной командой.
  2. Проверьте их размер через ls -l — он должен быть равен нулю.
  3. Подождите минуту и выполните touch notes.txt ещё раз. Посмотрите ls -l: что изменилось у этого файла?

§3Копирование и перемещение

Две команды-близнецы отличаются одной деталью: одна оставляет оригинал на месте, другая — нет.

cpcopy · копировать
cp {расположение1}… {расположение2}

Создаёт копию. Оригинал остаётся на месте.

-r
рекурсивно — копировать каталог со всем содержимым
-i
спрашивать перед перезаписью существующего файла
mvmove · переместить
mv {расположение1}… {расположение2}

Перемещает файл. По исходному пути его больше не будет. Ключ -r не нужен: каталоги перемещаются целиком сами собой.

Правило про второй аргумент важно помнить: если файлов копируется несколько, последним аргументом обязан быть каталог — иначе непонятно, во что их всех превращать. А если файл один, второй аргумент может быть новым именем.

Попробуйте на своей системезадание 3
  1. Скопируйте созданные в прошлом задании файлы в папку test.
  2. Убедитесь, что оригиналы остались на месте: ls и ls test.
  3. Переместите один из файлов в папку test/dir1.
  4. Проверьте, что по старому пути его больше нет.
  5. Скопируйте весь каталог test под именем test_backup. Без ключа -r команда откажется работать — прочитайте её сообщение.

§4Переименование

Отдельной команды для переименования в Linux нет — и она не нужна. Переименование это частный случай перемещения: файл переносится туда же, где лежал, но под другим именем.

Важно: перезапись происходит молча

Если файл с новым именем уже существует, mv и cp перезапишут его без единого вопроса, и старое содержимое исчезнет. Привычка, которая однажды спасёт вам работу: добавлять ключ -i — тогда команда спросит подтверждение перед перезаписью.

Попробуйте на своей системезадание 4
  1. Переименуйте любой из своих файлов.
  2. Создайте два файла a.txt и b.txt, запишите в них разные имена через touch и ls, затем выполните mv a.txt b.txt. Сколько файлов осталось?
  3. Повторите тот же опыт с ключом -i и сравните поведение команды.
  4. Переименуйте каталог test_backup в backup. Работает ли mv с каталогами так же, как с файлами?

§5Удаление каталогов: rmdir

rmdirremove directory
rmdir {путь}…

Удаляет каталог — но только если он пуст. Непустой каталог команда трогать откажется, и это её главное достоинство.

Осторожность rmdir выглядит неудобной, пока не вспомнить, что удаление в Linux необратимо. Отказ удалить каталог, в котором что-то лежит, — это защита от случайной потери данных, а не каприз.

Попробуйте на своей системезадание 5
  1. Удалите каталог test/dir3 — он пуст, всё пройдёт гладко.
  2. Попробуйте удалить каталог test/dir1, в котором лежит перемещённый ранее файл. Что произошло? Прочитайте сообщение.
  3. Аналогичным образом попробуйте удалить через rmdir любой файл. Почему не выходит?
Почему rmdir не удаляет файлы

Команда предназначена ровно для одной задачи — удаления пустых каталогов, и файл для неё объект неподходящего типа: Not a directory. Такая узкая специализация типична для Unix: каждая утилита делает одну вещь, зато делает её предсказуемо.

§6Удаление файлов: rm

rmremove · удалить
rm [аргументы]… {путь}…

Удаляет файлы. С ключом -r удаляет каталоги вместе со всем содержимым — целыми деревьями.

-r
recursive — рекурсивно, вместе с содержимым
-i
спрашивать подтверждение по каждому файлу
-f
force — не задавать вопросов вообще
Важно: корзины нет

Удалённое командой rm не попадает никуда — оно просто перестаёт существовать. Восстановление возможно только специальными средствами и далеко не всегда. Особенно опасна связка rm -rf: она рекурсивно и без единого вопроса стирает всё, до чего дотянется. Прежде чем нажать Enter, прочитайте путь ещё раз — глазами, целиком. Особенно если он начинается с /.

Полезная привычка: перед удалением по шаблону выполните ту же команду с ls вместо rm. Так вы увидите точный список того, что исчезнет.

Сначала посмотреть

ls test/*.txt

Список файлов, которые попадут под шаблон.

Потом удалять

rm test/*.txt

Та же команда, но результат необратим.

Попробуйте на своей системезадание 6

Только внутри своего домашнего каталога. Все пути в этом задании начинаются с ~/test. Не экспериментируйте с rm в системных каталогах и никогда не запускайте эту команду с путём /.

  1. Теперь с помощью rm удалите любой файл.
  2. С помощью rm -r удалите каталог test/dir1 со всем его содержимым.
  3. Перед удалением остального посмотрите, что там лежит: ls -R ~/test.
  4. Осуществите удаление всего дерева каталогов, начиная с каталога test.
  5. Проверьте результат: ls ~.
Как потренироваться безопасно

Создайте отдельную песочницу и работайте только в ней: mkdir -p ~/sandbox/a/b, touch ~/sandbox/a/f1 ~/sandbox/a/b/f2. Тогда любая ошибка в rm -r ~/sandbox стоит ровно ничего — каталог создаётся заново одной командой.

Усложнённая задачабез подсказки

Соберите в домашнем каталоге такую структуру одной-двумя командами: каталог projects, внутри него lab1, lab2, lab3, а в каждом из них — пустые файлы main.c и readme.txt. Затем: скопируйте lab1 целиком под именем lab4, переименуйте в нём main.c в main_v2.c и удалите каталог lab2 вместе с содержимым. Проверьте итог командой ls -R ~/projects.

§8Проверьте себя

Зачем mkdir ключ -p, если каталог можно создать и без него?

Без -p команда создаёт только последний каталог пути и требует, чтобы все родительские уже существовали. Ключ -p создаёт всю цепочку сразу — за одну команду вместо нескольких.

Почему команда называется touch, а не create?

Её основное назначение — обновление временных отметок файла: времени изменения и времени последнего доступа. «Прикоснуться, ничего не поменяв». Создание пустого файла — побочный эффект, который стал самым популярным способом её применения.

Чем отличается cp a.txt b.txt от mv a.txt b.txt?

После cp останутся оба файла с одинаковым содержимым. После mv останется только b.txt: это переименование, то есть перемещение в то же место под другим именем.

Когда rmdir удобнее, чем rm -r?

Когда вы хотите удалить каталог, только если он действительно пуст. rmdir откажется работать с непустым каталогом и тем самым предупредит о том, что внутри что-то есть. rm -r в такой ситуации молча удалит всё вместе с содержимым.

Как безопасно проверить, что именно удалит rm ~/test/*.log?

Выполнить ту же команду, заменив rm на ls: ls ~/test/*.log. Шаблон раскроет оболочка, и вы увидите точный список файлов, которые попадут под удаление. Дополнительно помогает ключ -i: он спросит подтверждение по каждому файлу.

§9Шпаргалка

Создать каталог mkdir test mkdir -p a/b/c
Создать файл touch notes.txt touch a.txt b.txt
Копировать cp notes.txt test/ cp -r test backup
Переместить и переименовать mv notes.txt test/ mv old.txt new.txt
Удалить rmdir empty_dir rm file.txt rm -r dir
Подстраховаться cp -i mv -i rm -i ls путь # перед rm

Итог главы

Каталоги создаёт mkdir (с ключом -p — сразу всю цепочку), пустые файлы — touch. Копирование и перемещение выполняют cp и mv с одинаковым синтаксисом; разница в том, остаётся ли оригинал. Переименование — это mv в то же место под другим именем. Удаляют rmdir (только пустые каталоги) и rm (файлы, а с -r — деревья каталогов). И главное, что стоит унести из этой главы: корзины в Linux нет, поэтому перед rm путь читают глазами, а не по памяти.
